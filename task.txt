# HANCI — MASTER AGENTIC BUILD / MIGRATION / KNOWLEDGE INJECTION PACK
## September 2026 — terminal-first, Supabase-backed, provider-neutral

This file is the master handoff for the Hanchi project. It is intentionally written as a product/engineering specification, not a generic "make an AI app" prompt.

The agent must inspect before editing, work in bounded phases, test after each meaningful change, preserve existing data, and never claim completion without evidence.

---

# 0. OPERATING MODE

You are acting as a Principal Engineer, Agentic Systems Architect, Product Engineer, and QA engineer.

You must work as an **agentic engineer**, not a blind vibe coder.

Before changing anything:

1. Inspect the repository and current architecture.
2. Define the desired outcome.
3. Define non-goals.
4. Identify affected files, database objects, provider dependencies, and risks.
5. Define acceptance tests.
6. Make the smallest safe change.
7. Run the relevant verification.
8. Inspect the diff.
9. Record what changed and what remains.

Rules:

- Never rewrite stable code without evidence.
- Never create duplicate sources of truth without proving the existing source cannot serve the requirement.
- Never silently delete historical data.
- Never silently convert inference into fact.
- Never let old context override current confirmed context.
- Never expose secrets.
- Never reintroduce Lovable Cloud.
- Never reintroduce Lovable AI.
- Never claim a feature works because the UI exists.
- Never build five unrelated features in one unverified edit.
- Prefer reversible, incremental changes.

### Current-state rule

Current confirmed information has priority over historical records.

### Decision history

Never delete a changed decision.

Store the chain:

```text
old decision
→ superseded
→ newer decision
→ current decision
```

- "What is the current decision?"
